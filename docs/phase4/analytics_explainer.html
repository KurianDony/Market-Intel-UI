Suburb Analytics — Methodology Explainer v2

Pilot suburbs: Strathfield, Castle Hill, Enmore, Liverpool · metric_version pilot2-2026.06 · Demand = G1 seekers · Supply = G2 listings (G1 never used for supply) · Price = G1 p50 · click any row for formula, code & meaning.

1.Data cleaning

Every input passes a cleaning stage before any metric runs. The governing rule is report, don't silently drop: a value that fails a rule is excluded from that metric and counted — never quietly altered or imputed.

The cleaning principles

PrincipleWhat it doesWhy
Range-clip rentWeekly rent must be $50–$2000, else excluded from rent stats.Kills scrape glitches without touching real values.
Cap outliersCeiling absurd derived values (e.g. days-on-market ≤120).One freak value can't drag a median/average.
Safe divideAny ratio with a zero/missing denominator returns "no value".No fake infinities from thin data.
G2-anchored, dedupedOne row per listing; supply & listings anchored to the latest G2 week.No double-counting; counts and charts describe the same moment.
Size cap (≤5)Small-house analysis ignores houses with >5 rooms or >5 tenants.Flatmates caps that field at 6, so 6+ is a lumped, unreliable bucket.
Sanity gatesPercentiles must be ordered; histogram must reconcile to the count.Catches corrupted distributions before a chart.
Low supply is NOT cleaned out — a week with few rooms is a real soft-market signal, kept as-is. And G1 supply (rooms_offered) is not used at all for supply maths; only G2 listing counts are.

What was actually removed (live, this run)

Rent data was clean — nothing dropped for range/null/duplicates. The meaningful exclusion is the ≤5 size cap: 6+ bedroom houses are set aside from the small-house view (they're the capped/lumped bucket).

2.Metrics calculated

The 3-lens framework. Demand, Supply and Price are each reported through three comparison lenses, so a number always has context:
• Lens 1 — this suburb over time: now, vs last week, and a 4-week trend.
• Lens 2 — vs its area: the average across other suburbs in the same area, plus this suburb's rank.
• Lens 3 — vs Sydney: the average across all suburbs.
Confidence gate (runs first)
C1·C2 Confidence badge GREEN / AMBER / RED — is there enough data to trust?

What it shows

The colored chip is a go/no-go on the whole card. It answers "does this suburb have enough real data to believe the numbers?" — based on G2 listing volume and recency. GREEN = enough listings and recent weeks present. AMBER = thin (<8 listings) or short history (fewer than 4 of the last weeks). RED = under 3 listings, too little to mean anything. Low G1 supply is not penalised (that's a soft market, not bad data).

Formula

C1 (sample): RED if listings<3 · AMBER if listings<8 · else GREEN C2 (recency): weeks_present = distinct G2 weeks in last 28 days if weeks_present < 4 → knock GREEN down to AMBER

Worked example

Strathfield = GREEN (109 listings, full cycle). Enmore = AMBER (61 listings but only 3 of the last 4 weeks loaded).

Code

if total_listings is None or total_listings < 3:   level = "RED"
elif total_listings < 8:                           level = "AMBER"
else:                                              level = "GREEN"
if weeks_present_4 < 4 and level == "GREEN":       level = "AMBER"
The three headline metrics × 3 lenses
DEM Demand — seekers how many people are looking, 3 lenses

What it shows

The number of people searching in the suburb (G1 "people looking"), seen three ways: trend over the last 4 weeks, versus other suburbs in the area (with rank), and versus the Sydney average. Higher / rising = more competition for rooms.

Formula (same for all three headline metrics)

now = latest weekly value wow_delta = now − last week area_avg = mean of the latest value across suburbs in this area vs_area% = 100 × (now − area_avg) / area_avg sydney_avg = mean of the latest value across ALL suburbs vs_sydney% = 100 × (now − sydney_avg) / sydney_avg

Code

now  = series[-1][1]
last = series[-2][1]
wow  = now - last
area_avg   = mean(latest value for each suburb where area matches)
sydney_avg = mean(latest value for every suburb)
vs_area_pct   = 100 * (now - area_avg)   / area_avg
vs_sydney_pct = 100 * (now - sydney_avg) / sydney_avg
SUP Supply — G2 listings how much competing stock, 3 lenses (no G1)

What it shows

The count of live listings in the suburb, from G2 only. Same three lenses. This is the real measure of how much stock a room competes against. G1's rooms_offered is never used here.

Worked example

Strathfield now 109 listings, area average ~25 (rank 1 of 20), Sydney average ~24 → it's a far larger market than typical (+338% vs area). Enmore jumped +16 week-over-week (34→61).

Formula

supply = G2 total_listings at the latest G2 week (then the same now / area / Sydney lens maths as Demand)
PRC Price — p50 typical rent, 3 lenses

What it shows

The median advertised rent (p50, read off the G1 price curve), across the same three lenses. Lets you see if a suburb is pricier or cheaper than its area and than Sydney, and which way it's trending.

Worked example

Strathfield p50 $300, down $20 w/w, ~10% below both its area ($333) and Sydney ($330). Enmore $360, ~9% above Sydney.

How p50 is read

def gen_percentile_from_bars(bars, p):
    total = sum(b["relative_height"] for b in bars)
    cum = 0.0
    for b in bars:
        cum += b["relative_height"]
        if cum >= total * p:
            return int(b["price"])
Demand ratios (each shown as a band)
R1 G1 demand ratio seekers per room, shown as a ±band

What it shows

Flatmates' own demand ratio (seekers per room). Because the source value is coarse, we show it as a small asymmetric band rather than a false-precise point: a ratio of 3 displays as 2.5–3.4.

Formula

band(R) = [ R − 0.5 , R + 0.4 ] e.g. 3 → 2.5–3.4 , 2 → 1.5–2.4

Code

BAND_LO, BAND_HI = -0.5, 0.4
def ratio_band(r):
    return {"value": r, "low": r + BAND_LO, "high": r + BAND_HI}
R2 Listings per seeker competing supply each seeker faces

What it shows

How much live stock there is per person searching = G2 listings ÷ seekers. Higher means a looser market (lots of choice per seeker). We flipped this from "seekers per listing" because that came out near-zero and the band went negative; listings-per-seeker gives a readable magnitude.

Worked example

Strathfield 109 listings ÷ 3 seekers = 36.3 (band 35.8–36.7) → very loose. Liverpool 8.7 → tighter.

Formula

listings_per_seeker = G2 listings / G1 seekers band = [ value − 0.5 , value + 0.4 ]

Code

lps = safe_div(listings, seekers)   # G2 / G1-seekers
ratio_band(lps)
Pricing analysis
SH Small-house: do people pay more for a smaller house? median rent by size 1–5

What it shows

The business question directly: median weekly rent of a room, grouped by how many bedrooms (and separately, occupants) the house has, for sizes 1–5. Houses with 6+ rooms/tenants are excluded (flatmates caps the field at 6, so it's unreliable). If smaller sizes show higher rent, people are paying a premium for a room in a smaller house.

The finding (all four suburbs)

Smaller houses ask more — consistently. Strathfield 1br $560 vs 5br $300; Enmore peaks at 2br $525; Castle Hill and Liverpool the same direction. Sample sizes (n) are shown on every bar, since some buckets are thin.

Formula

for size s in 1..5: median_rent[s] = median( rent_pw of listings with bedrooms == s ) verdict = compare smallest (1–2 br) vs largest (4–5 br) medians

Code

for L in live_listings:
    rent = clip_rent(L["rent_pw"])
    b = L.get("bedrooms")
    if isinstance(b, int) and 1 <= b <= 5:
        by_bed[b].append(rent)
median_rent = {s: median(v) for s, v in by_bed.items()}
Underlying base + self-checks
B2·B4·B7 Percentile band · dispersion · skew the shape behind the price

What they show

The p50 headline sits on the full price distribution: the band p10–p90 (cheap to premium), dispersion = p90−p10 (how tight the market is), and skew = average − p50 (whether a tail of pricey listings pulls the mean up).

Formula

band = { p10, p20, p50, p80, p90 } dispersion = p90 − p10 (and p80 − p20) skew = avg_rent − p50
QA GIGO self-checks does the maths add up?

What it shows

Automatic integrity checks each run; a failure flags the card rather than trusting it.

percentile_monotonic : p10 ≤ p20 ≤ p50 ≤ p80 ≤ p90 histogram reconciles : placed + dropped = live listings histogram vs counts : |placed − total_listings| ≤ 5

3.Graphs & visuals

chart 4-week trend sparkline on Demand, Supply, Price

What it is

The little bar strip under each headline metric — the last four weekly values, so you see direction at a glance (rising supply, falling rent, etc.).

How it's calculated

Each bar = that week's value, scaled to the tallest bar in the window. Built from the same weekly series the lens maths uses; no extra computation.

chart Small-house bars median rent by house size 1–5

What it is

Five bars (1br…5br), each the median room rent for that house size, with the dollar value and sample size (n) labelled. A downward slope left-to-right = smaller houses cost more.

How it's calculated

Bar height ∝ median rent for that bedroom count (see metric SH above). Houses with 6+ bedrooms are excluded entirely.

tiles Lens comparison row now · area · Sydney

What it is

For each headline metric: the current value with a ▲/▼ week change, then two comparison chips — "area (avg, rank, %)" and "syd (avg, %)". The % is this suburb relative to that baseline.

How it's calculated

Directly from the 3-lens block; the % figures are 100 × (now − baseline) / baseline.

tiles Ratio band tiles the two demand ratios

What it is

Two amber tiles showing each ratio as a range (G1 demand ratio band, and listings-per-seeker band) rather than a single false-precise number.

How it's calculated

See metrics R1 and R2 — value ± the fixed band.
